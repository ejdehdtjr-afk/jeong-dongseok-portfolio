## 브라우저에서 확인한 내용

Windows Codex 내장 Chromium 브라우저의 로컬 미리보기에서 확인했다.

1. `examples/delivery-demo.png`를 파일 선택으로 입력해 한국어 문장과 영문 URL을 추출했다. 출력에는 ‘주소 오류로 배송이 보류되었습니다’, ‘오늘 안에 카드 정보를 입력하세요’, `http://delivery-check.example/confirm`이 포함됐다. 구분점은 원본 ‘·’가 ‘ㆍ’로 읽혀 직접 수정이 필요한 사례도 확인됐다.
2. 자동 확인 후 민감 정보·압박 표현·링크가 구분되어 표시되고 실제 호스트·HTTP 이유가 보였다.
3. 메시지를 수정하면 기존 결과·근거 영역이 숨겨지고 점검 선택 수가 0으로 초기화됐다.
4. 정상 일정 문장 재분석은 위험 신호 0·확인 필요 5로 표시됐다. 단어 미검출을 안전으로 단정하지 않았다.
5. 빈 메시지의 자동 확인은 입력 안내를 표시했다.
6. 이미지가 아닌 JSON 파일 선택은 허용 형식 안내와 함께 거절됐다.
7. 인식 시작 직후 취소하면 미리보기가 사라지고 글자 가져오기 버튼이 비활성화됐다.
8. 모바일 viewport 390×844로 설정해 확인했다. 관찰된 문서 clientWidth·scrollWidth는 모두 375로 가로 넘침이 없었다. 실제 휴대전화 기기 검증은 아니다.

## 검증의 한계

- 가상 예시의 기능 동작 확인이며 실제 피싱 탐지 정확도나 피해 감소를 검증한 것은 아니다.
- 흐릿한 이미지·다양한 기기·모든 폰트에 대한 인식 품질 보장은 없다.
- 실제 기관 소유권·최종 리다이렉트·악성 페이지는 확인하지 않는다.
- 부정문·문맥 판별은 후속 단계다. ‘인증번호를 절대 알려주지 마세요’에도 관련 표현이 검출된다.
- 메시지·이미지 비전송은 구현 코드를 확인한 결과다. 전체 네트워크 패킷 감사나 별도 보안 심사를 수행한 것은 아니다.
- 10MB·2천만 화소 제한과 120초 실패 안내는 코드에 구현했다. 제한 경계값 전체에 대한 브라우저 검증은 수행하지 않았다.
- 신고 저장은 기존 기능이며 이번 검증에서 실제 신고를 생성하지 않았다.
