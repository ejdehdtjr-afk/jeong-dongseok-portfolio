# 중간 점검 2차 제출 입력 문구 — 피디(P.D.)

## 이번에 만든 것

1차의 스크린샷 점검 기능에 이어 택배·배송, 가족·지인, 금융·대출, 공공기관·수사기관, 계정·서비스, 기타의 6개 유형별 추가 질문을 구현했습니다. 각 유형의 세 질문에 답하면 상황별 주의 근거를 결과에 반영하고, 유형을 바꾸면 이전 답변과 결과를 초기화합니다. 키워드로 제안한 유형은 사용자가 수정할 수 있습니다. 또한 메시지 속 링크와 별개로 KISA·인터넷우체국·경찰청 등의 공식 확인 경로와 적용 범위·확인일을 안내했습니다.

일부 예방·금지 문구와 거래 완료 안내를 구분해 오탐을 줄이고, 상품권·신분증·원격제어 관련 행동 요구를 보완했습니다. 고정된 1차 분석기와 2차 분석기로 같은 가상 사례 30개를 비교하는 화면과 변경·누락 필터도 만들었습니다. 가상 개발 사례에서 정상 위험 신호 표시는 7/10에서 0/10, 피싱 누락은 5/10에서 2/10으로 바뀌었습니다. 독립적인 실제 탐지 성능 검증은 아니며 남은 두 누락 사례도 공개했습니다.

## 확인하는 방법 · 3단계 이내

1. 결과물에서 ‘가족 사칭 의심’을 선택하고 ‘메시지 자동 확인’을 누릅니다.
2. 가족·지인 질문 세 개에 아니요·예·예로 답한 뒤 ‘답변을 반영해 다시 점검’을 누릅니다. 상황별 이유와 공식 확인 경로를 보고, 유형을 바꿨을 때 답변·결과가 초기화되는지 확인합니다.
3. 상단 ‘가상 사례 30개로 1차·2차 비교하기’에서 비교를 실행하고 ‘결과가 달라진 사례’와 ‘2차에서 놓친 피싱 사례’ 필터를 확인합니다.

## 바뀐 점과 그 이유

1차는 텍스트 신호만으로 판단을 보조했고 실제 상황은 항상 확인 필요로 남겼습니다. 이번에는 본인이 예상한 연락인지, 기존 연락처로 확인했는지, 민감한 행동을 요구하는지 묻도록 했습니다. 사용자가 긍정적으로 답했더라도 기존 자동 위험 신호는 유지하고, 잘 모르겠다는 답변도 안전으로 바꾸지 않도록 했습니다.

‘인증번호를 알려주지 마세요’ 같은 예방 안내가 위험으로 표시되던 문제를 일부 문형에서 보완했습니다. 다만 모든 부정문·문맥을 이해하는 것은 아닙니다. 1차 로직을 보존하고 같은 가상 사례로 비교해 달라진 결과와 여전히 놓치는 사례를 확인할 수 있게 했습니다. 이미지 삭제 버튼이 예시 선택 동작까지 실행하던 문제도 함께 수정했습니다.

## AI에게 맡긴 일과 내가 판단한 일

AI에게 맡긴 일: 유형별 질문·답변 반영, 공식 출처 조사와 링크 구성, 예방 문구 처리·행동 요구 보완, 비교 화면·가상 사례 작성, 자동 테스트와 브라우저 검증, 계획서·제출 문구 작성을 맡겼습니다.

내가 판단한 일: 기존 피싱 방지 앱의 프리미엄 과제를 1차에 이어 2차까지 진행하기로 정했습니다. 기존에 정한 추가 질문·공식 확인 경로·오탐 및 누락 비교의 범위를 이어갔습니다.

※ 구현·검증은 AI가 수행했습니다. 제출자가 직접 사용한 경험·추가 판단·수정 사항이 있으면 실제 내용에 맞춰 보완합니다.
