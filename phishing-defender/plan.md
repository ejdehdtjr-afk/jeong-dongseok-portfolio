## 프로젝트 목표

의심 문자·메신저를 받은 사람이 위험 신호와 자신의 상황을 확인하고, 이미 행동했다면 피해 확산을 줄이기 위한 다음 조치를 찾도록 돕는다. 사기 여부나 실제 발신자를 확정하는 서비스로 표현하지 않는다.

## 대상

낯선 링크·인증정보 요청을 혼자 판단하기 어렵거나, 링크 클릭·정보 입력·앱 설치·송금 뒤 무엇을 먼저 해야 할지 모르는 일반 사용자. 스마트폰에서 짧은 안내를 읽는 상황을 우선한다.

## 핵심 기능 3가지

1. 스크린샷·텍스트 점검: 기기 내 OCR, 의심 문구 강조, 링크의 실제 호스트 표시. 1차 완료.
2. 상황별 추가 확인: 6개 유형의 질문, 공식 확인 경로, 고정된 1차와의 가상 사례 비교. 2차 완료.
3. 행동 뒤 대응과 제보 관리: ‘이미 행동했어요’ 바로가기, 복수 행동별 순서가 있는 안내, 원문을 제외한 편집 가능한 요약, 신고 접수 상태 조회·정정 요청. 이번 3차 범위.

## 이번 구현

- 첫 화면에 ‘이미 행동했어요’ 바로가기를 두고 링크 클릭·인증정보 입력·개인정보 제공·앱 설치·송금 중 여러 개를 고를 수 있게 한다. 송금과 악성 앱 의심 대응을 앞에 둔다. 메시지 분석을 건너뛰어도 안내를 볼 수 있다.
- 공식 자료에 맞춰 112·거래 금융회사·118 등 직접 이용할 경로를 안내한다. [금융위원회 피해 대응](https://www.fsc.go.kr/po010105/83034?curPage=77&srchBeginDt=&srchCtgry=&srchEndDt=&srchKey=&srchText=), [KISA 스미싱 안내](https://www.kisa.or.kr/1020601)를 근거로 한다.
- 점검 요약에서 원문·스크린샷·상황 질문 답변·원본 링크·호스트를 제외한다. 일부 번호 형식도 감지해 주의를 표시한다. 사용자가 편집한 뒤 복사 또는 텍스트로 저장한다. 자동 가림은 완전하지 않으므로 공유 전 직접 검토한다.
- 예전 ‘동일 번호 5건이면 신고 필요’ 문구를 제거한다. 새 제보는 사실 확인 전의 접수 상태로 시작한다. 접수 조회 코드로 본인 제보 상태를 확인하고 정정 이유를 보낼 수 있다. 운영자 확인, 오인 신고, 검토 중 상태는 서버에서만 바뀐다. 정정은 원 제보를 즉시 삭제하거나 검증 상태로 바꾸지 않는다.
- 접수·조회·정정용 Supabase SQL을 기존 프로젝트에 적용했다. 서버가 멈췄거나 연결되지 않은 경우에는 신고 폼을 비활성화하고 그 사실을 화면에 표시한다.

## 확인 방법 · 3단계

1. 첫 화면 ‘이미 행동했어요’에서 ‘돈을 이체하거나 결제했어요’와 ‘앱을 설치했어요’를 선택해 112·금융회사 조치가 먼저 보이는지 확인한다.
2. ‘의심스러운 배송 문자’ 자동 확인 후 결과의 점검 요약을 읽고, 원문·링크 주소가 빠졌는지 확인한 뒤 내용을 수정해 복사하거나 저장한다.
3. 신고 영역에서 서버 연결 상태와 접수 버튼을 확인한다. DB 검증은 가상 번호의 접수·조회·정정을 한 트랜잭션 안에서 실행하고 롤백했으며 시험 제보가 0건 남았다.

## 완료 기준

- [x] 기존 분석 없이 행동별 안내 표시, 복수 선택·우선순위 검증.
- [x] 요약 미리보기·직접 수정·복사·텍스트 저장, 원문 제외 검증.
- [x] 신고 상태·정정 RPC와 접수 코드 방식의 앱·SQL 구현.
- [x] Supabase 관리자 SQL 적용, 익명 API 접근과 가상 제보의 접수·조회·정정·롤백 검증. 공개 앱 연결 확인.
- [ ] 실제 사용자 3~5명에게 용어·다음 행동의 이해도를 확인. AI 모의 사용은 실제 사용자 조사로 세지 않는다.

## 개인정보·운영 한계

메시지·이미지·대응 선택·요약은 브라우저에서 처리한다. 전화번호·신고 글과 정정 이유는 기능을 사용할 때 Supabase에 저장된다. 조회 비밀값은 서버에 해시로 보관하고, 브라우저에는 접수 코드만 로컬 저장한다. 코드를 가진 사람이 상태와 정정 기능을 이용할 수 있어 공유하지 않도록 안내한다. 공개 운영을 지속하려면 보존 기간, 관리자 검토, 남용 방지 정책을 확정해야 한다. 기존 1·2차 가상 사례 30개는 독립 성능 평가가 아니다.

## 역할

사용자는 기존 피싱 방지 앱을 프리미엄 최종 과제로 발전시키고 ‘이미 행동했어요’ 및 신고 처리 상태·정정 기능을 추가하기로 결정했다. AI는 구현·공식 자료 확인·가상 검증·문서 작성을 맡았다. 실제 사람을 인터뷰하거나 사용자 판단을 대신 기록하지 않는다.
