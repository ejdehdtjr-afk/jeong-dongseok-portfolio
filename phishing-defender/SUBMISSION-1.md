# 중간 점검 1차 제출 입력 문구 — 피디(P.D.)

## 이번에 만든 것

무료 과정 마지막 B 과제로 제출했던 피싱 점검 앱을 이어서, 의심 메시지를 더 쉽게 입력하고 판단 근거를 확인할 수 있도록 개선했습니다. 이번 1차에서는 문자·메신저 스크린샷을 선택하면 브라우저 안에서 한국어·영어 글자를 추출하고, 사용자가 인식 오류를 수정한 뒤 메시지를 점검하는 기능을 추가했습니다. 민감 정보·금전 관련 표현, 긴급·압박 표현, 링크를 원문에서 색상으로 구분해 표시하고, 링크의 실제 호스트와 HTTP·IP·일부 단축 주소 등 확인이 필요한 이유를 보여줍니다. 이미지 미리보기·삭제·인식 취소, 입력 수정 시 이전 분석 초기화도 구현했습니다. 메시지·이미지는 서버에 보내지 않으며 기존 전화번호 신고 저장과 구분해 안내했습니다.

## 확인하는 방법 · 3단계 이내

1. 결과물 URL에서 ‘개인정보 없는 가상 문자 이미지 내려받기’를 누른 뒤, 내려받은 이미지를 ‘스크린샷 선택’으로 골라 ‘이미지에서 글자 가져오기’를 누릅니다.
2. 추출된 글자를 원본과 비교해 수정하고 ‘메시지 자동 확인’을 누릅니다.
3. ‘오늘 안’·‘카드 정보’·링크의 구분 표시와 실제 호스트 delivery-check.example, HTTP 확인 이유가 보이는지 확인합니다. 메시지를 바꾸면 이전 결과가 사라지고 다시 분석할 수 있습니다.

## 바뀐 점과 그 이유

기존 앱은 텍스트를 직접 붙여넣어야 했고, 분석 결과에 ‘요청 표현을 찾았다’는 설명만 있어 원문에서 근거를 찾기 어려웠습니다. 스크린샷 입력으로 복사 부담을 줄이고, 원문 강조와 실제 호스트 표시로 사용자가 무엇을 확인해야 하는지 알 수 있도록 바꿨습니다. 글자 인식은 틀릴 수 있으므로 자동으로 판정을 확정하지 않고 사용자가 수정한 후 분석하도록 했습니다. 또한 특정 단어가 없다는 이유만으로 안전으로 표시하지 않도록 보완했습니다.

## AI에게 맡긴 일과 내가 판단한 일

AI에게 맡긴 일: 기존 코드 분석, 스크린샷 글자 인식·원문 강조·호스트 분석 구현, 테스트 작성·실행, 브라우저 동작 확인, 계획서와 제출 문구 정리를 맡겼습니다.

내가 판단한 일: 마지막 B에서 만든 피싱 앱을 프리미엄 과제로 이어가기로 정했고, 우선순위 높은 기능을 단계별로 확장하되 이번 제출 범위를 중간 점검 1차와 그에 맞는 plan.md까지로 정했습니다.

※ 위 기능 검증은 AI가 수행했습니다. 제출자가 직접 사용한 뒤 추가 판단·수정 사항이 있으면 본인의 실제 경험에 맞춰 보완합니다.

## 다음에 할 일

2차에서는 사칭 유형별 추가 질문으로 사용자의 상황을 확인하고 공식 확인 경로를 안내할 계획입니다. 정상·피싱·애매한 사례를 모아 오탐·누락과 수정 전후 결과를 비교하겠습니다. 최종 단계에서는 링크 클릭·정보 입력·앱 설치·송금 등 이미 취한 행동에 따른 대응 안내와 결과 요약을 추가할 계획입니다. 현재는 단어 기반 규칙의 문맥·부정문 한계가 남아 있으며 피싱 탐지 정확도 향상을 입증한 것은 아닙니다.
