- `node --check`: `app.js`, `response.js`, `reports.js` 통과.
- `git diff --check`: 공백 오류 없음.

## 브라우저 모의 사용

- 첫 화면에서 ‘송금’과 ‘앱 설치’를 함께 선택. 112·금융회사 지급정지 요청이 맨 앞에 나오고 118 악성 앱 상담이 이어짐.
- 배송 가상 문자 자동 확인 후 요약 확인. 위험 신호와 행동은 표시되고 원문·URL·실제 호스트는 요약에 복사되지 않음.
- 요약 텍스트를 직접 수정해 복사했고 성공 안내를 확인함.
- 모바일 너비 390px에서 본문 너비와 스크롤 너비가 모두 375px로 가로 넘침이 없었음. 실제 휴대전화 기기 테스트는 아님.
- 기존 Supabase 프로젝트가 일시 중지돼 있었으나 2026-11-05에 재개됨. 복구 완료 뒤 SQL을 적용하고 `pd_create_report`, `pd_report_status`, `pd_correct_report`, `pd_report_health` 네 함수 존재를 확인함.
- 익명 공개 API에서 health 200, 입력 오류 400, 없는 조회 코드·정정 대상 null을 확인함. 이는 잘못된 요청이 제보를 만들지 않는다는 확인이다.
- SQL 트랜잭션에서 가상 번호로 접수→올바른 코드 조회→틀린 코드 거부→정정 요청을 모두 통과한 뒤 의도적 예외로 롤백함. 시험 번호의 잔여 제보 0건 확인.
- 공개 앱에서 ‘신고 서버가 연결됐습니다’와 활성화된 제보 접수 버튼을 확인함. 실제 사람의 전화번호로 신고를 생성하지 않음.
- 공개 앱 연결 화면을 `evidence-3/04-report-connected.png`에 보관함.

## 남은 확인

- 운영자 검토 상태 변경과 정정 처리 절차를 운영 기록으로 확인.
- 실제 브라우저에서 제출 폼의 접수→조회→정정 왕복은 개인정보나 시험 제보를 서버에 남기지 않도록 아직 수행하지 않았다. DB 함수의 왕복은 롤백 시험으로 확인했다.
- 실제 사용자 사용성 확인. AI 모의 사용과 가상 사례는 사람의 평가가 아님.

## 주의

대응 안내는 공식 자료를 바탕으로 한 일반 안내이며 실제 피해 여부를 판단하지 않는다. 자동 가림으로 모든 개인정보를 찾을 수 없어 요약은 공유 전 사용자가 확인해야 한다. 신고 상태의 ‘접수됨’은 검증 완료가 아니다.
